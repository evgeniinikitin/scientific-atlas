# Научный атлас

Работающий русскоязычный прототип платформы для визуализации архитектуры сложных научных проблем. В интерфейсе есть шесть самостоятельных интерактивных карт, поиск и фильтры, карточки вершин, связанные материалы, избранное, личный кабинет и научная стена.

> Это прототип. Карты не являются исчерпывающей научной классификацией. Материалы, помеченные как демонстрационные, не выдаются за реальные библиографические записи.

## Быстрый запуск

Требуется Node.js 20+ (рекомендуется 22).

```bash
npm install
npm run dev
```

Откройте `http://localhost:3000`. Без переменных окружения публичный атлас полностью работает на локальных данных.

Демонстрационная сессия открывается кнопкой на странице входа.

Она явно обозначена как локальная, хранится только в `localStorage` и не имитирует реальную серверную авторизацию. Регистрация, восстановление пароля и синхронизация данных требуют Supabase.

## Команды

```bash
npm run dev          # локальная разработка
npm run typecheck    # строгая проверка TypeScript
npm run lint         # ESLint
npm test             # Vitest
npm run test:e2e     # Playwright (при первом запуске: npx playwright install chromium)
npm run build        # production-сборка
npm start            # запуск production-сборки
```

## Supabase

1. Создайте проект Supabase.
2. Выполните миграцию `supabase/migrations/202607220001_initial_schema.sql` через Supabase CLI или SQL Editor.
3. Выполните `supabase/seed.sql`.
4. Скопируйте `.env.example` в `.env.local` и заполните:

```env
NEXT_PUBLIC_SUPABASE_URL=https://PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
```

После перезапуска приложение автоматически использует Supabase Auth. Публичные карты продолжают иметь локальный fallback; пользовательские данные в текущем прототипе локальны в demo mode и готовы к замене репозиториями Supabase.

Storage предусмотрен полем `profiles.avatar_path`. Создайте приватный bucket `avatars` и политики доступа владельца перед загрузкой реальных аватаров.

RLS включён для всех таблиц. Публично читаются только опубликованные карты и материалы; профили, история, уведомления и избранное доступны только владельцу. Создание экспертной рецензии ограничено ролями `expert`, `moderator`, `administrator`.

## Upstash

Заполните `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`, чтобы включить Redis-ограничение запросов через `src/lib/rate-limit.ts`. Без них limiter безопасно пропускает локальные запросы. Этот модуль предназначен для подключения к server actions публикаций и форм при переходе от прототипа к production.

## Netlify

1. Подключите репозиторий в Netlify.
2. Build command и publish directory уже заданы в `netlify.toml`.
3. Добавьте Supabase/Upstash env vars в настройках сайта.
4. Deploy. Плагин `@netlify/plugin-nextjs` подключается Netlify из конфигурации.

Перед деплоем выполните `npm run build`. Для OAuth добавьте Netlify URL в Supabase Auth → URL Configuration.

## Реализовано

- редакционная главная со светлой и тёмной темами;
- каталог трёх дисциплин и фильтруемые страницы направлений;
- 6 проблем и 72 содержательные вершины (по 12 на карту);
- шесть разных композиций и наборов связей;
- pan, zoom, minimap, центрирование, fullscreen, перетаскивание;
- фильтры типа/статуса и поиск по вершинам;
- режимы графа, списка и материалов;
- drawer узла с доказательностью, соседями, статьями, копированием ссылки и навигацией;
- локальное избранное, история, профиль и настройки;
- реальный Supabase login/sign-up/recovery при наличии env;
- честная локальная demo-session при отсутствии backend;
- научная стена и валидируемая форма демонстрационной публикации;
- адаптивные desktop/tablet/mobile состояния, keyboard focus, empty/loading/error feedback;
- SQL-схема, RLS, seed, Vitest и Playwright.
